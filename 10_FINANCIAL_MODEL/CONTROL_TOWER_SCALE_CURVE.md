# Control Tower Scale Curve — Cycle 11

Conceptual, variable-based — no invented salary data. Testing whether Control Tower
economics improve with portfolio scale, and whether that creates a pilot-evaluation trap.

## Cost components

- **Fixed capability cost** (built once, largely independent of site count): the
  attribution methodology, accountability boundary framework, governance process design,
  risk corridor design — the intellectual/process capital this project has substantially
  already built across Cycles 2-10. A genuine sunk-ish fixed cost that amortizes across
  however many sites eventually use it.
- **Site-variable cost:** Contract Director + Contractor Integration Lead — the two roles
  `ZERO_BASED_CONTROL_TOWER_ORG.md` found don't share well across sites.
- **Complexity-variable cost:** scales with contractor count, data fragmentation, turnaround
  intensity at each site — can vary significantly site to site, independent of site count.
- **Central platform cost:** Commercial Controller, Data Analyst, VVB support pool,
  reliability methodology maintenance — real and ongoing, but needs a minimum number of
  accounts to amortize sensibly. A central function serving one account is not really
  "shared," it is relabeled dedicated cost.

## The critical finding: the pilot trap

**At one site, essentially all "shared" central cost is entirely loaded onto that one
customer.** A pilot could look expensive and uneconomic purely because there is no
portfolio to spread central cost across — not because the model is fundamentally flawed.
This is a real, plausible trap, explicitly confirmed by this analysis: **yes, a pilot could
falsely appear uneconomic**, and this must be an explicit interpretive caution for whoever
evaluates the first deal's P&L.

The converse discipline follows directly: the first pilot's true economics should be
evaluated using **Model A (Site Heavy)** assumptions — no shared-cost amortization assumed —
not Model B/C's shared-cost logic, to avoid an artificially optimistic first-deal business
case built on scale economics that do not yet exist.

## Conceptual curve

- **One site:** central cost fully loaded onto one account; Model A is the only honest
  evaluation basis; economics likely look weak even if the underlying thesis is sound.
- **Three sites:** central cost begins to spread meaningfully; Model B's hybrid logic starts
  to make real sense; still early to justify Model C's platform-heavy central investment.
- **Ten sites:** central platform cost is well-amortized; Model C becomes genuinely
  attractive; this is roughly where the "moat" candidates identified in
  `03_STRATEGIC_THESIS/SYSTEMATIC_CAPABILITY_MAP.md` (cross-site data, a genuinely
  replicable attribution engine) could start to show real value.

**Getting to ten sites requires surviving the economics of the first few without that
benefit** — a real chicken-and-egg funding and patience problem for the provider, not solved
by this analysis, only named.
