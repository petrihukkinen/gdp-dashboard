# Work Classification — Cycle 11

**The model fails if Category D becomes material.** This classification exists specifically
to catch that failure mode before it happens, not after.

## A. Existing contract management work
Work a competent integrated maintenance provider should already perform, regardless of
AMOR: Site Manager function, Work Management Lead function, most of the Reliability Lead
function, most of the Commercial Controller function, most of the Contract Director
function (baseline relationship management, without the accountability-boundary and
governance-board layer).

## B. Enhanced orchestration work
Additional work specifically required by the AMOR accountability architecture: the
Contractor Integration Lead's *formal* cross-contractor authority (beyond typical
subcontract administration); Event 4 evidence-packaging discipline
(`07_KPI_ATTRIBUTION/event4_decision_tree_v3.md`); accountability-boundary documentation and
governance-board participation (`03_STRATEGIC_THESIS/ACCOUNTABILITY_BOUNDARY.md`); the
Causal Connection Map, *only if* a module requiring it is ever activated (currently
recommended not to build, per Cycle 7).

## C. Customer work transferred to provider
Work currently performed by the customer that moves with broader scope: contractor
scheduling/dispatch coordination, work-order tracking, contractor invoice reconciliation —
*if genuinely transferred*, not assumed. See `CUSTOMER_DUPLICATION_TEST.md`. Precedent
exists: AMOR 2020 was structured around an actual ~350 FTE personnel transfer
(`EVIDENCE_REGISTER.md` A2).

## D. New bureaucracy — created only because the AMOR model itself requires it
The categories genuinely at risk of sliding here if organizational discipline isn't
maintained:
- A **dedicated** (not shared) Digital Specialist or Data Analyst per site, when the
  zero-based analysis found both should default to centralized/pooled.
- A fully-staffed, standing Value Validation support function per site, when it should be
  event-driven and centralized — Event 4 should be rare by design.
- Building the Causal Connection Map "just in case" rather than only if a specific module
  requires it (already rejected once, Cycle 7 — the temptation could resurface).
- Governance meeting cadence beyond what the actual claim volume justifies (Cycle 6's
  bureaucracy-break-even logic applies here directly).

## Discipline required
Every role added to a real delivery organization should be traceable to Category B or a
genuinely transferred piece of Category C — never justified by "the framework calls for
this role" alone. This is an execution discipline the zero-based design enables but cannot
enforce by itself — see `CONTROL_TOWER_COST_RED_TEAM.md`, item 1.
