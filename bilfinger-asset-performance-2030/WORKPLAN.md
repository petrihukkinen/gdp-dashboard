## Cycle 2 — proposed priorities (in order)

Cycle two should go deep, not broad. Recommended sequence, gated on Petri's answers to the cycle-1 priority open questions:

1. **`05_KPI_ATTRIBUTION/` — build the actual attribution decision-tree and Value Validation Board charter.** This is the single most load-bearing, least-proven part of the concept (Risk R1/R2). Needs Petri's answer to open question #4 (a real Neste/AMOR dispute-resolution example) to ground it in lived experience rather than first-principles design.
2. **`07_DIGITAL_AI/` — run every candidate module (from the brief's list) through the discipline test** (business problem, data needed, data ownership/availability, decision improved, financial value). Expect several modules to be cut or marked "not yet viable" — that is a feature of rigor, not a gap to fill in later. Directly addresses Risk R8.
3. **`08_FINANCIAL_MODEL/` — put real ranges on the illustrative numbers** (Phase 3 fee %, gainshare split, Value Validation Board resourcing cost) using AMOR's own figures as one data point and any numbers Petri can share/estimate from ABB experience as a second. This is what turns "directionally credible" into "financially coherent" per the STRATEGIC_THESIS.md checker pass.
4. **`06_OPERATING_MODEL/` — address internal Bilfinger adoption (Risk R6)** explicitly: what changes for regional P&L owners, sales incentives, and legal/risk sign-off; do not leave this as customer-facing only.
5. **`03_CUSTOMER_VALUE/` — pressure-test Section 1–3 of STRATEGIC_THESIS.md against a specific (even if disguised) customer profile**, once Petri answers open question #7 on a realistic pilot account.
6. Only after 1–5 are stress-tested: **`09_RISK_REGISTER/`** gets a full second-pass update, **`13_100_DAY_PLAN/`** gets drafted, and **`12_INTERVIEW_QA/`** gets built from whatever new sharp edges cycle two surfaces.
7. **`10_EXECUTIVE_DECK/` and `11_CEO_PITCH/` stay empty** until 1–4 above are done — per CLAUDE.md rule #11, polished production before the architecture is stress-tested would lock in unvalidated claims.

## What would change this plan

- If Petri confirms Bilfinger already runs some form of gainshare contract, item 1 changes from "design a mechanism" to "study and extend an existing one" — materially easier and should be reprioritized immediately.
- If the target role turns out to be narrower/more operational (e.g., a single country or service-line leadership role) rather than a group-strategy mandate, the whole concept should be rescoped smaller before cycle two proceeds — see open question #1.
- If confidentiality concerns (open question #5, Risk R13) require fully anonymizing the AMOR/Neste material, `AMOR_ANALYSIS.md` and any deck built from it need a rewrite pass to generalize identifying detail before anything leaves this project directory.
